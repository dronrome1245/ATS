# Функциональные требования ATS

## Торговый контур

| ID | Требование |
|---|---|
| `FR-TR-001` | Система формирует сигнал только по утверждённой версии торговой гипотезы. |
| `FR-TR-002` | Для каждого сигнала фиксируются входные данные, причина решения, версия стратегии и время. |
| `FR-TR-003` | Правила входа, выхода, стопа, удержания и повторного входа должны быть детерминированы. |
| `FR-TR-004` | Система учитывает торговые сессии, фильтр спреда и запреты торговли, если они определены гипотезой. |
| `FR-TR-005` | Управление открытой позицией не должно обходить защитный контур. |

## Защитный контур

| ID | Требование |
|---|---|
| `FR-RK-001` | Защитный контур применяет максимальный риск сделки независимо от торгового сигнала. |
| `FR-RK-002` | Ограничиваются максимальный объём, число позиций и совокупный риск. |
| `FR-RK-003` | Дневной предел потерь и предел общей просадки блокируют новые сделки. |
| `FR-RK-004` | Мартингейл, неограниченное усреднение и автоматическое повышение риска после убытка запрещены. |
| `FR-RK-005` | При чрезмерном спреде, некорректной котировке или неизвестном состоянии новые сделки запрещены. |
| `FR-RK-006` | Аварийная остановка должна быть доступна независимо от логики сигнала. |
| `FR-RK-007` | После достижения критического лимита автоматическое пополнение или перезапуск торговли запрещены. |

## Исполнение и состояние

| ID | Требование |
|---|---|
| `FR-EX-001` | Каждому торговому намерению присваивается устойчивый идентификатор для защиты от повторного ордера. |
| `FR-EX-002` | После перезапуска система восстанавливает состояние по фактическим позициям и журналу. |
| `FR-EX-003` | Неизвестная открытая позиция переводит систему в безопасный режим. |
| `FR-EX-004` | Отклонение, частичное исполнение, requote, проскальзывание и задержка фиксируются отдельно. |
| `FR-EX-005` | Расчётный и фактический размер позиции сохраняются для сверки. |

## Журналирование

| ID | Требование |
|---|---|
| `FR-LG-001` | Журнал содержит все решения, запреты, запросы на исполнение, ответы брокера и ошибки. |
| `FR-LG-002` | Запись журнала включает версию кода, параметры, инструмент, время и состояние защитного контура. |
| `FR-LG-003` | Журнал не содержит секретов доступа. |
| `FR-LG-004` | Для демо и реальных этапов поддерживается shadow-сверка ожидаемого и фактического поведения. |

## Тестирование

| ID | Требование |
|---|---|
| `FR-TS-001` | Поддерживаются воспроизводимые бэктесты с фиксированными данными, параметрами и моделью издержек. |
| `FR-TS-002` | Поддерживается визуальная проверка сделок. |
| `FR-TS-003` | Поддерживаются стресс-сценарии спреда, задержки, проскальзывания, пропуска сигналов и сбоев. |
| `FR-TS-004` | Поддерживается Монте-Карло или блочный bootstrap для оценки хвостовой просадки. |
| `FR-TS-005` | Финальный экзамен запускается только на замороженной версии и ранее не просмотренном периоде. |

## Управление версиями

| ID | Требование |
|---|---|
| `FR-VR-001` | Каждая значимая версия стратегии имеет идентификатор, кодовую ревизию и набор параметров. |
| `FR-VR-002` | Результат эксперимента неизменно связан с конкретной версией. |
| `FR-VR-003` | Существенная перенастройка создаёт новую версию и не наследует автоматически допуски прежней. |
