# Security Policy

## Область защиты

Репозиторий не должен содержать данные, позволяющие получить доступ к торговому счёту, VPS, терминалу, брокерскому кабинету, почте или платёжным средствам.

## Запрещено коммитить

- логины и пароли;
- API-токены и ключи;
- приватные ключи и сертификаты;
- номера счетов и персональные идентификаторы;
- файлы конфигурации с секретами;
- журналы, содержащие секретные параметры подключения;
- полные брокерские выписки с персональными или платёжными данными.

## Разрешённый подход

- секреты хранятся во внешнем менеджере секретов или защищённом локальном хранилище;
- в код передаются через переменные окружения или защищённый runtime-механизм;
- в Git сохраняются только имена необходимых переменных и правила проверки их наличия;
- тестовые данные должны быть обезличены;
- журналирование не должно раскрывать секреты.

## Инцидент

При попадании секрета в Git недостаточно удалить его новым коммитом. Нужно немедленно отозвать секрет, выпустить новый и очистить историю репозитория допустимым способом.
