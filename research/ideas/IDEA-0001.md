## Observation

BTCUSDT spot may exhibit periods in which directional movement persists across multiple completed 1H bars after price enters a clearly defined trend/breakout state relative to prior completed bars.

If such persistence exists, a deterministic long/flat rule that uses only information available after each 1H bar closes may be able to capture part of the subsequent upward movement before a defined exit condition indicates that the trend has weakened or reversed.

No claim is made yet that this effect exists, is economically meaningful or survives costs.

## Preliminary rationale

A plausible mechanism is gradual adjustment rather than instantaneous incorporation of all information into price. Persistent order flow, delayed reaction, attention cascades or position adjustment can in principle create multi-bar continuation.

Published time-series-momentum/trend-following literature documents trend persistence as a research phenomenon across multiple markets and horizons. That literature does not establish that the same effect exists in BTCUSDT 1H data, so transfer to this instrument/timeframe is the proposition to test rather than an assumption.

The rationale is therefore non-circular: the Idea is not based on an ATS backtest or on a parameter set selected because it made money.

## Expected effect

- Direction/type of effect: `POSITIVE_CONTINUATION_AFTER_UPWARD_TREND_OR_BREAKOUT_STATE`
- Expected observable consequence: after a preregistered upward trend/breakout state formed only from completed 1H bars, subsequent BTCUSDT price movement should be more positive than an appropriate unconditional/non-signal baseline over one or more **predeclared** forward horizons.

The exact state definition, forward horizons and failure threshold are intentionally deferred to `HYP-0001`. They must be fixed before observing the prototype result.

## Cheapest useful test

After `HYP-0001` freezes one deterministic trend/breakout definition and a bounded set of forward horizons:

1. load a frozen BTCUSDT 1H dataset through the M2 Dataset Manifest/loader path;
2. compute the signal using only completed bars;
3. measure forward price continuation after signal bars versus a declared baseline;
4. run a simple long/flat replay with action no earlier than the next information-available point;
5. apply explicit cost sensitivity;
6. report the result without optimizing the rule after seeing it.

This cheap test should be able to weaken or kill the Idea before Candidate admission or production engineering.

## Known risks of false inference

- look-ahead from using the final 1H bar value before the bar is actually closed;
- same-close execution that assumes an unavailable fill after signal computation;
- choosing lookback, threshold, horizon or exit rule after observing results;
- repeated testing/multiple-comparison bias;
- regime dependence and non-stationarity in crypto markets;
- BTCUSDT instrument-selection bias because the first reference line deliberately chooses one prominent current symbol;
- exchange/market-structure changes through time;
- fee, spread and slippage sensitivity at 1H turnover;
- missing or revised archive files;
- timestamp-unit or bar-boundary mistakes;
- quote-asset/stablecoin-specific effects;
- interpreting historical trend-following literature as direct evidence for BTCUSDT rather than provenance.
