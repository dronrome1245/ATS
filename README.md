# ATS

**ATS** — исследовательский проект автоматизированной торговой системы, в котором переход от идеи к реальной торговле разрешается только через последовательные ворота допуска.

Главная цель проекта — не максимизировать результат бэктеста, а как можно раньше и дешевле обнаружить ошибочную торговую гипотезу, недостаточную устойчивость, дефект программной реализации или несоответствие реального исполнения модели.

## Текущее состояние

- Жизненный цикл: `RESEARCH`.
- Текущие ворота: `G01_RISK_MANDATE`.
- Реальная торговля: запрещена.
- Масштабирование: запрещено.
- Торговая гипотеза: не утверждена.
- Брокер, юрисдикция, инструмент, тип счёта и исполнительная платформа: не утверждены.
- Численные пределы финансового эксперимента: не утверждены.

## Принцип проекта

Ни прибыльный бэктест, ни работающий код, ни несколько удачных реальных сделок сами по себе не разрешают переход к следующей стадии. Допуск создаётся только совокупностью:

1. заранее установленного критерия;
2. воспроизводимого доказательства;
3. зафиксированной версии кода, параметров и данных;
4. отсутствия неразрешённого блокирующего риска;
5. явного решения владельца проекта там, где требуется принятие финансового риска.

## Тринадцать ворот

| ID | Ворота | Основной результат |
|---|---|---|
| `G01` | Риск-мандат | Утверждённые пределы капитала, убытка, просадки и срока эксперимента |
| `G02` | Юрисдикция, брокер и счёт | Проверенная спецификация юридической природы инструмента и торгового счёта |
| `G03` | Торговая гипотеза | Однозначная спецификация одной стратегии |
| `G04` | Архитектура и защитный контур | Разделённые торговая и защитная системы с журналированием и аварийной остановкой |
| `G05` | Данные и протокол разбиения | Зафиксированные источники, периоды разработки, валидации и финального экзамена |
| `G06` | Разработка и первичный бэктест | Корректный код и базовая статистика с реалистичными издержками |
| `G07` | Устойчивость и валидация | Плато параметров и устойчивость по периодам и режимам |
| `G08` | Независимый экзамен | Однократный положительный тест замороженной версии на ранее не просмотренном участке |
| `G09` | Стресс-тест, Монте-Карло и live-протокол | Хвостовая оценка риска, правила остановки и замороженные условия реального эксперимента |
| `G10` | Демо-приёмка | Техническая надёжность без необъяснённых операций и критических сбоев |
| `G11` | Центовое исполнение | Подтверждение реальных издержек и исполнения при минимальной цене ошибки |
| `G12` | Минимальный обычный счёт и масштабирование | Повторяемость результата и ступенчатое увеличение риска только по новой статистике |
| `G13` | Допуск к использованию прибыли как дохода | Подтверждённая реальная устойчивость и правила вывода прибыли |

Подробные критерии находятся в `00_Управление_проектом/МАТРИЦА_ВОРОТ.md`.

## Быстрый старт

1. Открыть `00_НАЧАТЬ_ЗДЕСЬ.md`.
2. Проверить текущее состояние в `03_СОСТОЯНИЕ_ПРОЕКТА.yaml`.
3. Выполнить только действие из `02_СЛЕДУЮЩИЙ_ШАГ.md`.
4. Перед изменением статуса ворот собрать доказательства по `00_Управление_проектом/МАТРИЦА_ВОРОТ.md`.
5. Запустить `python tools/validate_repo.py`.

## Ограничение ответственности

Репозиторий организует исследование, разработку, контроль риска и доказательства. Он не гарантирует прибыльность стратегии и не заменяет проверку законодательства, налоговых последствий, условий конкретного брокера и пригодности торговли для владельца капитала.
