## Назначение

До реализации base loader нужно сделать dataset identity и semantics явными и машинно проверяемыми. Manifest описывает dataset; он не является самими данными и не подменяет Data Feasibility Review.

M2-003 должен определить минимум:

1. stable Dataset ID и version/change rules;
2. source/source-snapshot identity without invented vendor;
3. storage/reference format and schema identity;
4. coverage start/end and applicable universe/scope metadata;
5. timezone and timestamp representation;
6. observation/event time versus decision-time information availability;
7. deterministic ordering key and equal-time tie-break rule;
8. duplicate, missing, malformed and out-of-order data policy;
9. transformation/preparation lineage and code/reference identity;
10. checksum/integrity metadata where applicable;
11. known limitations/gaps and their research impact;
12. local/external storage reference without committing licensed/raw datasets;
13. Pydantic validation with safe YAML loading;
14. structural tests using synthetic non-market manifests only.

## Completion gate

Перед закрытием M2-003 на exact commit выполнить `uv run --frozen python tools/verify_repo.py` и получить `ATS LOCAL CI: PASS`. GitHub Actions не используется как критерий завершения.

## Definition of Done

`ATS2-M2-003` can close when a Dataset Manifest can be loaded and validated deterministically from the canonical template, invalid timestamp/order/integrity semantics are rejected, material dataset changes require a new version, and no actual market/vendor/source facts are invented to prove the schema.

## Ограничения

Do not build the base data loader in M2-003 beyond the minimum file/manifest read needed to validate the schema. Do not implement Strategy API, replay, costs or analytics. Do not select Reference Strategy #1.

After M2-003 the next dependency-driven task is `ATS2-M2-004 — Base data loader` under WIP discipline.
