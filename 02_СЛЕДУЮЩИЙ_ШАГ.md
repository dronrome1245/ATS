## Назначение

Нужно выбрать минимальный technology stack для первого M2 vertical research platform, используя `governance/program/REFERENCE_CONSUMER_PROFILE.md` как requirements contract.

ADR должен определить минимум:

1. основной research language/runtime;
2. environment/package/lock strategy;
3. минимальный data representation/loading approach;
4. configuration/manifest parsing approach;
5. module/package boundaries для data/replay/strategy interface/costs/analytics/runner;
6. testing framework и deterministic fixture approach;
7. numerical/data dependencies, только если они действительно нужны Consumer Profile;
8. reproducibility strategy для local/CI runs;
9. способ хранить большие/лицензируемые datasets вне Git при стабильных manifests;
10. rejected alternatives и причину, почему более тяжёлый stack пока не нужен;
11. explicit out-of-scope: broker/live execution, portfolio engine, news ingestion, distributed/HPC, GUI as requirement.

## Decision criteria

Выбранный stack должен быть:

- достаточным для deterministic ordered-data research;
- простым для clean-environment reproduction;
- testable в CI/local environment;
- совместимым с M1 Experiment manifest/result/conclusion;
- пригодным для incremental M2 capabilities без premature production architecture.

## Definition of Done

`ATS2-M2-001` можно закрыть, когда ADR даёт однозначный технический baseline, достаточный для начала `WBS-2.2`, `WBS-2.3` и `WBS-2.5`, с явными trade-offs и rejected alternatives.

## Ограничения

Не выбирать Reference Strategy #1, market, instrument, broker, live risk model или capital allocation. Не строить live/execution architecture под видом research stack.
